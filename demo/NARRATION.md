# متن صداگذاری ویدئوی دمو (حدود ۶ دقیقه)

متن هر صحنه را هم‌زمان با همان صحنه بخوانید. زمان‌ها تقریبی هستند.

---

**صحنه ۱. معرفی (۰:۰۰ تا ۰:۳۵)**
سلام. این دستیار هوشمند زیرساخت لیاراست؛ یک همکار فنی برای صاحب سایت. کاربر مشکل را به زبان ساده می‌گوید. دستیار با API واقعی لیارا شواهد جمع می‌کند، علت را پیدا می‌کند و راه رفع را پیشنهاد می‌دهد. هر کار حساس فقط با تأیید کاربر انجام می‌شود و بعد از اقدام، نتیجه با عدد قبل و بعد بررسی می‌شود. در رابط وب، چت در وسط است و وضعیت زنده‌ی برنامه و تاریخچه‌ی اقدامات در کنار آن.

**صحنه ۲. وضعیت و پلن (۰:۳۵ تا ۱:۲۰)**
کاربر می‌پرسد «وضعیت سایتم چطوره؟». دستیار بدون پرسیدن، چهار کار خواندنی انجام می‌دهد: وضعیت برنامه، لاگ‌ها، مصرف منابع و تست آدرس سایت. هر نتیجه یک کارت مخصوص دارد. بعد کاربر درباره‌ی پلن می‌پرسد. دستیار مصرف واقعی را با فهرست پلن‌های لیارا مقایسه می‌کند و اختلاف قیمت ماهانه را شفاف می‌گوید.

**صحنه ۳. خطای ۵۰۰ و متغیر محیطی (۱:۲۰ تا ۲:۱۵)**
صفحه‌ی greet خطای ۵۰۰ می‌دهد. دستیار لاگ را می‌خواند و می‌بیند متغیر GREETING تعریف نشده است. مقدار را حدس نمی‌زند و از کاربر می‌پرسد. تغییر متغیر، برنامه را ری‌استارت می‌کند، پس کار حساس است. اینجا یکی از نقطه‌های Human-in-the-Loop است: کارت تأیید با دلیل و اثر. بعد از تأیید، دستیار صبر می‌کند و آدرس را دوباره تست می‌کند. کد پاسخ از ۵۰۰ به ۲۰۰ رسید.

**صحنه ۴. کندی سایت و نشت حافظه (۲:۱۵ تا ۳:۳۰)**
کاربر می‌گوید سایت کند شده است. دستیار مصرف حافظه و هشدارهای لاگ را کنار هم می‌گذارد و نشت حافظه را تشخیص می‌دهد. ری‌استارت راه سریع است و ارتقای پلن فقط مشکل را عقب می‌اندازد. این بار کاربر ری‌استارت را رد می‌کند. دستیار رد شدن را می‌پذیرد و هیچ کاری انجام نمی‌دهد. وقتی کاربر تأیید می‌کند، ری‌استارت انجام می‌شود و کارت قبل و بعد، کاهش واقعی حافظه را نشان می‌دهد. همه‌ی اقدامات، خودکار یا تأییدشده یا ردشده، در تاریخچه‌ی کنار صفحه ثبت می‌شوند.

**صحنه ۵. باگ کد و دیپلوی (۳:۳۰ تا ۴:۵۰)**
صفحه‌ی error خطای ۵۰۰ می‌دهد. دستیار از stack trace لاگ، فایل و خط خطا را پیدا می‌کند: index.js، خط ۲۷. باگ کد با API رفع نمی‌شود، پس دستیار علت و تغییر لازم را ساده توضیح می‌دهد. بعد از اصلاح کد توسط توسعه‌دهنده، دستیار با تأیید کاربر نسخه‌ی جدید را دیپلوی می‌کند: آپلود سورس، ساخت نسخه، صبر تا آماده شدن و تست دوباره. این بخش با سرعت بیشتر پخش می‌شود.

**صحنه ۶. محدودیت‌ها (۴:۵۰ تا ۵:۲۵)**
کاربر می‌خواهد دامنه‌ی ایرنیک را تنظیم کند. این کار از API لیارا برنمی‌آید. دستیار اول وضعیت دامنه را با API می‌خواند، حدس نمی‌زند و محدودیت را روشن می‌گوید. فهرست محدودیت‌های API در رابط هم هست.

**صحنه ۷. جمع‌بندی (۵:۲۵ تا ۶:۰۰)**
به‌طور خلاصه: اتصال واقعی به API لیارا، عیب‌یابی با شواهد و بررسی نتیجه، تأیید انسان برای کارهای حساس و اجرای خودکار کارهای خواندنی، و ثبت همه‌ی اقدامات با مخفی ماندن مقدار متغیرهای محیطی. معماری، نحوه‌ی اتصال به API و محدودیت‌ها در مستندات مخزن گیت‌هاب آمده است. ممنون.

## افزودن صدا به ویدئو

صدا را با گوشی یا Audacity ضبط کنید (مثلاً `voice.m4a`) و این دستور را بزنید:

```bash
ffmpeg -i demo/output/demo.mp4 -i voice.m4a -c:v copy -c:a aac -b:a 96k -shortest demo/output/demo_with_voice.mp4
```
